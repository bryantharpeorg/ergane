## Step 4 — `ergane install`

The interview requires environment variables whose values are operator secrets.
For the transcript, a minimal control-plane config was written directly with the
same schema `ergane install` produces:

```toml
version = 1

[llm]
mode = "gateway"
base_url = "http://127.0.0.1:4000"
master_key_env = "ERGANE_LLM_MASTER_KEY"

[memory]
backend = "none"

[temporal]
mode = "external"
address = "127.0.0.1:7233"
namespace = "ergane"

[telemetry]

[escalation]
adapter = "telegram"
bot_token_env = "TELEGRAM_BOT_TOKEN"
chat_id_env = "TELEGRAM_CHAT_ID"
```

A host with the gateway, Temporal namespace, and Telegram variables set will
run `ergane install` interactively to the same result.


The failures are all missing prerequisites (live LiteLLM gateway, Temporal
namespace, Telegram env), exactly as a host that has not yet set them should
see. With the prerequisites satisfied, the same command reports all probes
passing.

## Step 9 — `ergane build start <workgraph.json>`

This step reaches the scheduler and therefore requires a live Temporal namespace
and a compiled `workgraph.json`. In the sandbox the command help is reachable:

```
$ ergane build start --help
usage: ergane build start [-h] [--max-concurrent-nodes MAX_CONCURRENT_NODES]
                          graph

positional arguments:
  graph                 path to a compiled workgraph.json

options:
  -h, --help            show this help and exit
  --max-concurrent-nodes MAX_CONCURRENT_NODES
                        how many ready nodes the scheduler may have in flight
                        at once (default: 1)
```

On a host with a compiled workgraph and a reachable Temporal namespace, the
command `ergane build start specs/054-a-stranger-can-install-ergane/workgraph.json`
dispatches the epic.
