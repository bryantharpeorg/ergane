Ergane · the onramp

From a bare machine to a dispatched epic

Ergane is a software factory: Spec Kit feature specs go in, merged and verified code comes out. A Temporal workflow compiles each spec into a graph of user stories, dispatches every story to a headless coding agent in its own sandboxed worktree, runs deterministic gates and an LLM judge over what comes back, and lands what passes through a merge queue — with every token of spend attributed to the node that spent it.

written against v0.5.0 · 2026-08-27 · every command below is real; the demo was run from this page, from cold, and passed

Before anything else

Prove it in one command

You do not have to take any of this page's word for it. The released demo boots the whole factory — engine, Temporal, LiteLLM gateway, Postgres — from one file, and runs one real story end to end in front of you. Docker is the only thing you install; the kernel underneath it has to agree to one more thing, named in the trap below. You need an Ollama API key; the demo's gateway fronts Ollama Cloud. 

# exporting the key is the opt-in: the demo spends a few
# attempts' worth of tokens on it, and nothing else does
export UPSTREAM_MODEL_API_KEY=<your ollama key>

curl -fsSL https://github.com/bryantharpeorg/ergane/releases/latest/download/compose.yaml \
  | docker compose -f - up

First boot is the slow one — Postgres initialises and the gateway applies its whole migration history before it answers a health check, so the show starts a few minutes in. The install transcript that scrolls past carries two [FAIL] lines of its own: gh is unauthenticated on a stock host, and the gh in the image may be too old to declare baseRefOid. Neither stops a demo that never lands anything, and setting GH_TOKEN is optional. If the agent's first attempt fails its gate, that is part of the show too: you will watch the recovery ladder produce a second attempt and pass.

The halt statement is the epic's last word, not the stack's. The status render prints it above the node's own line, and the engine, the gateway and Postgres go on running and logging once the demo driver finishes — nothing exits, so press Ctrl-C when you have seen enough. The two sentinels the demo writes live in the named volumes, which is what stops a restart from spending your key twice; it also means a second up in the same directory finds the work already done and says so. To watch it again from cold, take the volumes with it: docker compose -p <project> down -v.

The trap

Docker is what you install; a user namespace is what you need. Every attempt runs inside bwrap, and on Ubuntu 23.10 and later kernel.apparmor_restrict_unprivileged_userns=1 denies that by default. The apparmor=unconfined this project sets does not lift it: AppArmor re-attaches a profile by executable path on exec, so bwrap inside the container is mediated by the host's policy, and without a profile granting it userns the sandbox dies at setting up uid map: Permission denied.

The demo probes for this before it spends anything and refuses by name if it fails, so the failure is cheap — but it is a refusal, not a run. On such a host, load a profile for bwrap once, with the two commands below. Hosts that do not restrict unprivileged user namespaces at all — most non-Ubuntu Linux, and Docker Desktop's own VM — need neither. 

# only on a host that restricts unprivileged user namespaces
printf '%s\n' 'abi <abi/4.0>,' 'include <tunables/global>' \
  'profile bwrap /usr/bin/bwrap flags=(unconfined) {' '  userns,' \
  '  include if exists <local/bwrap>' '}' | sudo tee /etc/apparmor.d/bwrap

sudo apparmor_parser -r /etc/apparmor.d/bwrap

Step 1 of 6

What you must already have

The demo carries its own stack. Running Ergane against your repositories does not, and one prerequisite in particular looks satisfied when it is not.

The trap

Your LiteLLM gateway must be database-backed. Every attempt runs on its own model-constrained, TTL'd virtual key: Ergane mints it with POST /key/generate, reads spend through GET /key/info and GET /spend/logs/v2, and revokes it when the attempt ends. Those endpoints exist only when LiteLLM has a DATABASE_URL. A config-only proxy answers chat completions perfectly, passes a casual smoke test, and fails at the first dispatch.

The gateway must also serve every model alias the persona registry names — ergane install --requirements prints the exact set, and ergane install --scan shows what a candidate endpoint actually offers before you commit to it.

Step 2 of 6

Install the CLI

There are two install paths and they are not interchangeable. To run Ergane against your own repositories, install the published distribution — the PyPI name is ergane-cli; the command it puts on your PATH is ergane: 

uv tool install ergane-cli

To work on Ergane itself, install from a checkout in editable mode:

git clone https://github.com/bryantharpeorg/ergane.git
cd ergane
uv venv
uv pip install -e .
The trap

The two paths resolve the persona registry from different places. An editable checkout reads the personas.yaml at its root, so edits take effect immediately. A published install reads the copy packaged inside the distribution — editing a personas.yaml in whatever directory you happen to be standing in changes nothing. ergane install reports the path it resolved, and that path is the answer.

Step 3 of 6

Configure the control plane

Run the interview and let it write the config. It asks for environment variable names, not values — set the variables in your shell before running anything that needs them. 

ergane install            # the interview; writes the control-plane config
ergane install --verify   # re-check without the interview, any time the environment changes
ergane install --scan     # discover what an endpoint offers first; writes nothing

llm.mode takes gateway or direct. Ergane accepts direct and tells you, at the moment you choose it, exactly what it costs: the declared key is handed to every attempt unexpiring, the registry's model bindings become a hint rather than a gate, and spend attribution goes away entirely, because there is no proxy to read per-key spend from. Those three properties are most of what the factory is for. Put a LiteLLM-shaped gateway in front and declare llm.mode = "gateway" unless you have decided to give them up.

Step 4 of 6

Install the worker

ergane worker install     # bridge + probe under systemd user supervision
ergane worker deploy      # freeze a commit into its own checkout and serve it

Install writes a versioned unit template rather than a worker; deploy starts an instance serving one frozen commit, so every epic finishes on the code it started with.

Step 5 of 6

Join a repository

ergane init --check       # judge readiness; writes nothing
ergane init               # enroll — resolves upward and asks before assuming the root
ergane init --wire        # also enable the merge queue + required checks on GitHub
ergane repo onboard <target-repo-path>   # register it with the engine

ergane init resolves upward to the nearest enclosing repository, which is not always the one you meant — when the directory you run it in is not itself the root, it names the root it resolved and asks first.

Step 6 of 6

Dispatch your first epic

ergane spec derive specs/<dir> --target-repo <target-repo-path>   # compile the spec to a work graph
ergane build start specs/<dir>/workgraph.json                     # put it on the floor

Then watch it the way the demo taught you: every story climbs the same six stops — merged is the last word, and ergane build status <epic-id> narrates the climb.

The trap

ergane spec landed scans the default branch unless told otherwise, and a factory does not necessarily land there. Pass --default-branch <branch> whenever the answer matters.

When you go

Leaving cleanly

One verb performs the whole teardown in the order that is safe — pause dispatch, forget repositories, stop the engine, remove the units, clear state — naming each step as it completes, and stopping if any step refuses: 

ergane uninstall --check     # print the plan a real run would follow; touches nothing
ergane uninstall             # the teardown itself; add --purge to also empty the state home
uv tool uninstall ergane-cli # the package itself is your package manager's job

For a partial exit, the fine-grained inverses still exist: ergane repo forget <repo-slug> unregisters one repository without touching its files, and ergane worker uninstall removes the worker units exactly as install wrote them. The control-plane config and the secrets beside it are kept on every path — removing those is yours to do by hand, deliberately.

The binding documents live in the tree: .specify/memory/constitution.md is what every dispatched agent obeys, docs/architecture.md is how the factory works, docs/decisions.md is the immutable decision log, and CONTEXT.md is the vocabulary. When this page and ergane status disagree, one of the two readings is older — and it is this one.
